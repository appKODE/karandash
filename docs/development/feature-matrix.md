# Feature matrix

Every feature Karandash has (documented, undocumented but real, and logic-only), with the three checks that must
all exist for it to count as done:

- **Behavior test**: a unit or contract test that fails if the feature breaks.
- **E2E**: a scenario run on the real binaries (the JVM `karandash.jar` and the host native `cli.kexe`). An id
  like `cfg-yaml` is a scenario in `tools/integration-tests/feature-e2e.sh` or one of its `e2e.d/*.sh` fragments,
  which run against the mock platform server (`tools/integration-tests/mock-server/mock-gitlab-api.py`: GitLab
  routes, plus one `mock_*.py` module per other API, such as GitHub, Gerrit, Azure DevOps and the fake LLM
  endpoints). A scenario that needs a host tool (`node`, `openssl`, `python3`) skips locally when the tool is missing
  and fails on CI (`CI=true`); the CI `test-integrations` job runs in the toolchain image
  (`docker/Dockerfile.toolchain`), which ships all three. A script name is another script under
  `tools/integration-tests/`. Every one of them runs from `tools/integration-tests/run-tests.sh` (gate part 1 and
  the CI `test-integrations` job). When a row has no scenario, the cell says why.
- **Doc**: the page that documents the feature for users. A row with no page is marked **gap**.

Run one scenario with `E2E_ONLY='^cfg-yaml$' bash tools/integration-tests/feature-e2e.sh`.
